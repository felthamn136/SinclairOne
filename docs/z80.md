# Z80 core

## Scope and status

`sinclair-cpu-z80` has no machine or frontend dependency. `Z80` owns registers,
interrupt state and instruction decoding; a host implements `Bus` for its
memory and ports. The Spectrum machine does not yet connect the CPU to a bus.
The core targets the NMOS Z80 instruction set, including the CB, DD, FD, ED,
DDCB and FDCB spaces. Unsupported hardware variants are not configurable.

The implementation returns nominal instruction T-states, **not** per-cycle
bus signals. It does not model WAIT/BUSREQ, contention, pin-level refresh, or
the undocumented internal WZ/Q registers. Some undocumented flag behavior and
interrupt edge cases therefore require further work. The core is not yet
certified against an exhaustive hardware-validated instruction suite; do not
treat these initial tests as proof of cycle-exact emulation.

In particular, `BIT n,(HL)` currently derives undocumented flag bits 3 and 5
from the HL address rather than the internal WZ latch, and `SCF`/`CCF` do not
model the previous-instruction Q latch. Repeating block instructions can also
produce different undocumented X/Y flags. These differences are observable
to software that relies on undocumented flags.

## Modules and API

```text
crates/sinclair-cpu-z80/
  src/
    lib.rs        public exports
    bus.rs        ordered memory, I/O and interrupt acknowledge interface
    cpu.rs        registers, interrupt handling, fetch and prefix dispatch
    base.rs       unprefixed opcode decoder and DD/FD substitutions
    cb.rs         CB, DDCB and FDCB bit operations
    ed.rs         ED instructions and block operations
  tests/
    acceptance.rs public-API integration tests
```

`Z80::new()` initializes all registers to zero for reproducibility; hardware
does not guarantee general-purpose power-on values. `reset()` resets control
state, PC, I and R, leaving general registers and SP unchanged. Public byte
fields and pair accessors expose the programmer-visible register set,
including alternate registers. Use `set_irq` for a level-sensitive INT line
and `request_nmi` for a latched NMI edge. `Bus::interrupt_acknowledge`
supplies the IM0 instruction or IM2 vector; its default is `0xff`. `Bus::reti`
is a notification for daisy-chain peripherals. The host can snapshot the
clonable CPU, but a stable serialized save-state format is not defined.

Each `step` processes one instruction, one repeated block iteration, one
interrupt response, or one HALT refresh cycle, returning its nominal T-states.
Bus accesses are performed in execution order; the caller must advance the
machine and its peripherals using the returned time. Because the bus does not
receive individual cycle timestamps, this API cannot yet emulate accurate
within-instruction contention or wait states.

## Decode and execution pipeline

1. At each instruction boundary, process latched NMI first, then an enabled
   INT, respecting EI's one-instruction delay. HALT remains stopped until an
   accepted interrupt and performs refresh cycles meanwhile.
2. Fetch an opcode (M1): advance PC and increment the low seven bits of R,
   preserving bit 7. Immediate data and indexed displacement fetches do not
   increment R.
3. Consume repeated DD/FD prefixes, with the last choosing IX or IY. ED
   ignores the index prefix. CB following an index prefix reads a displacement
   and a final non-M1 opcode. Each redundant prefix adds four T-states.
4. Decode the operation using its opcode fields; perform ordered bus accesses,
   update registers and flags, and return the taken/not-taken timing. Repeating
   ED instructions rewind PC for one iteration, so interrupts can be accepted
   between iterations.

Interrupt mode 0 executes an instruction supplied on interrupt acknowledge.
Every additional opcode M1 uses `interrupt_acknowledge`, while operand bytes
use `interrupt_data`; PC stays fixed during those fetches. The bus must
provide a stream of bytes for multi-byte IM0 instructions. The default
`interrupt_data` reads memory at the fixed PC and is suitable only when that
behavior is desired. Repeated block operations supplied via IM0 have not yet
been validated against hardware.
Mode 1 vectors to `0038`, and mode 2 reads a little-endian vector at `I:byte`.
NMI vectors to `0066`. RETN restores IFF1 from IFF2; RETI also notifies the
bus. Stack and vector addresses wrap at 16 bits.

## Opcode tables

The decoder uses `x = opcode >> 6`, `y = (opcode >> 3) & 7`,
`z = opcode & 7`, `p = y >> 1` and `q = y & 1`. Register columns in code
order are `B C D E H L (HL) A`; pair columns are `BC DE HL SP` (or `AF`
for push/pop). The table describes every base-byte group; prefix bytes
dispatch to the additional tables below.

| x | z | Opcode group |
|---|---|---|
| 0 | 0 | NOP, EX AF,AF', DJNZ, JR, JR cc |
| 0 | 1 | LD pair,nn; ADD HL,pair |
| 0 | 2 | LD via BC, DE or absolute memory |
| 0 | 3 | INC/DEC pair |
| 0 | 4–6 | INC r; DEC r; LD r,n |
| 0 | 7 | RLCA, RRCA, RLA, RRA, DAA, CPL, SCF, CCF |
| 1 | all | LD r,r matrix; `76` is HALT |
| 2 | all | ADD, ADC, SUB, SBC, AND, XOR, OR, CP with r |
| 3 | 0 | RET cc |
| 3 | 1 | POP pair; RET, EXX, JP (HL), LD SP,HL |
| 3 | 2 | JP cc,nn |
| 3 | 3 | JP nn, CB prefix, OUT, IN, EX (SP),HL, EX DE,HL, DI, EI |
| 3 | 4 | CALL cc,nn |
| 3 | 5 | PUSH pair, CALL nn, DD/ED/FD prefixes |
| 3 | 6 | ADD, ADC, SUB, SBC, AND, XOR, OR, CP with n |
| 3 | 7 | RST y*8 |

| Prefix | Coverage and selection |
|---|---|
| CB | `x=0`: RLC/RRC/RL/RR/SLA/SRA/SLL/SRL selected by y; `x=1`: BIT y,r; `x=2`: RES y,r; `x=3`: SET y,r |
| DD / FD | Substitute IX / IY for applicable HL, H, L and (HL) operations; indexed memory uses signed displacement. Prefixes ignored by an operation still consume time. |
| ED | Port I/O, 16-bit ADC/SBC and loads, NEG, RETN/RETI, IM, I/R transfers, RRD/RLD, block transfer/compare/I/O and repeating variants. Other ED encodings execute as 8-T NOPs. |
| DD CB d / FD CB d | CB operation on (IX+d)/(IY+d); non-BIT forms can also copy the result into the selected ordinary register. |

For conditional operations `y=0..7` selects `NZ, Z, NC, C, PO, PE, P, M`;
the shorter JR-cc group uses only `NZ, Z, NC, C`. CB `y=0..7` in the
rotate/shift group selects `RLC, RRC, RL, RR, SLA, SRA, SLL, SRL`.
The 16-bit arithmetic/transfer pair selected by `p=0..3` is `BC, DE, HL, SP`.

| 42 52 62 72 / 4A 5A 6A 7A | SBC / ADC HL,pair |
| 43 53 63 73 / 4B 5B 6B 7B | LD (nn),pair / LD pair,(nn) |
| 44 4C 54 5C 64 6C 74 7C | NEG and aliases |
| 45 55 5D 65 6D 75 7D / 4D | RETN and aliases / RETI |
| 46 4E 66 6E / 56 76 / 5E 7E | IM 0 / IM 1 / IM 2 and aliases |
| 47 4F 57 5F | LD I,A; LD R,A; LD A,I; LD A,R |
| 67 6F | RRD; RLD |
| A0 A1 A2 A3 | LDI, CPI, INI, OUTI |
| A8 A9 AA AB | LDD, CPD, IND, OUTD |
| B0 B1 B2 B3 | LDIR, CPIR, INIR, OTIR |
| B8 B9 BA BB | LDDR, CPDR, INDR, OTDR |

## Timing model

Nominal timings include prefixes and depend on the operation, operands, branch
outcome and repeat condition. For example, register CB operations take 8T;
BIT (HL) takes 12T; read-modify-write (HL) takes 15T. Indexed CB BIT takes
20T and indexed read-modify-write takes 23T. A repeating block instruction
takes 21T for a continuing iteration and 16T for the final one. NMI, IM1 and
IM2 responses take 11T, 13T and 19T respectively. IM0 adds interrupt
acknowledge time to the supplied instruction. External wait states are not
included.

## Acceptance and further validation

Run `cargo test -p sinclair-cpu-z80` and `cargo test --workspace`. The
acceptance tests exercise register sets, arithmetic flags, indexed and CB
operations, ED block repetition, EI delay, all interrupt modes, NMI and RETN.
They are representative, not exhaustive.

An independent run against 32 selected opcode files from
[SingleStepTests/z80](https://github.com/SingleStepTests/z80) at revision
`ebe1875d` checked 32,000 vectors against visible state, memory, I/O and
nominal T-states. It found no mismatches outside 1,509 comparisons of
undocumented X/Y bits excluded for the known `BIT (HL)` and repeating `LDIR`
limitations. Internal WZ/Q/P and EI-delay state and bus pin timing were not
compared. This sampled run does not cover every opcode.

Before calling the core hardware-accurate, compare every opcode and edge case
against independently generated, hardware-validated vectors; test bus ordering,
flags and timings, repeated prefixes, interrupts at every legal boundary,
refresh behavior and undocumented cases. Add cycle-level integration tests
against a Spectrum bus once a machine is connected.
